# Xenon 2 Megablast - code map

Generated by `tools/analyze68k.py` (recursive descent, capstone M68K) on the unpacked resident image (base $400) plus each of the 6 level modules (base $54E00). Machine-readable output: `generated/lane-d/entrypoints.json` (gitignored; rebuild with `tools/build_entrypoints.py generated/lane-d` after running the analyzer; per-level raw output `ana_l{1..6}.json/.lst`).

Confidence key: H = verified by reading code, M = inferred from hardware-register usage / structure, L = heuristic.

## 1. Architecture facts (all H unless noted)
- **Bare-metal after the stub**: no exec/dos/graphics library calls in the game image (the only `$4.l`/`jsr -$198(a6)` OpenLibrary is in the crack stub at $7052C). A6-jump-table translation is therefore not needed for the game; it is needed only if the stub/BS1 are ever recompiled (OpenLibrary(graphics) at stub $7052C, BS1 uses LoadView-style graphics.library; not in scope).
- Runs in supervisor mode with SR=$2000/$2700, interrupts: L1 $95E4, L2 $0FAC, L3 $20C2. All other vectors -> $7032 (cold restart).
- Code is contiguous in $400-$9657 (~40 KB), music engine $19F9E-$1B600, plus one level module per level at $54E00. Everything else is data/graphics.
- Addresses are used as 32-bit with 24-bit truncation (flag byte in top byte of pointers at $47D6 table); any `jmp/jsr` through registers must mask `& $FFFFFF`.
- Analysis totals (level 1 run): 369 resident functions/entry points, ~9.4K instructions decoded. 14 dynamic jump/call sites resident, ~4 per level module.

## 2. Boot / init (H)
`$400 bra.w $7032` -> `$7032: move #$2700,sr; bra $70F6` (installs bogus trace vector) `-> bra $763A` -> `$763C init` (399 insns):
set SSP=$435FC, fill vectors $08-$3FC with $7032, init vars (`$406=$4C700,$40A=$44000`, `$410`=4/5), install vectors ($64/$66 word-pair=$95E4, $68=$0FAC, $6C=$20C2), CIA setup ($BFD100 drive deselect, CIA-A/B ICR, keyboard), custom regs (BPLCON0, DIW, DDF, modulos, DMACON $87D0, INTENA $C02A, clear SPRxDATA, COP1LC=$1038), build y-offset table at $4321C, call `$7D9E`, `$6FE8` (wait-vbl helper), `$6BC8`, `$8220` (title/menu), `$8CB6` (options menu), `$917E` (load level file for `$E04`), then enter the **main loop** at $78A4.

## 3. Main loop (H structure, M names)
$78A4 wait for `$41C` change -> per frame, in order:
`$17D6` (blitter object pass; 213 insns, uses BLTCON/BLTAFWM... all Blitter regs) -> `$233A` -> `$202E` (wait frame pacing `$410`, swap `$406/$40A` screens, toggle copper list $1038/$1014 via `$700E`, write COP1LC + COPJMP1) -> `$88B6` (status/text draw, `a2=$54E1C` palette ptr) -> `$1F22` -> `$17D6` -> `$233A` -> `$6766` -> `$16BE` -> `$683C` -> **`jsr $54E24` (level module per-frame script/spawn)** -> `$35D4` (update all object lists) -> `$6372` (palette/fade, writes COLOR regs) -> `$61E6` -> `$3554`. Then key handling `$79D6`: raw keycode in `$9FF` looked up in 4-byte table at `$7954` (P pause $19 -> $79BA, ESC $45 -> $7800 (quit-to-menu), $40 -> $797A, default $79D6), `jmp (a0)` at $7952.
Level load/transition: `$8FF2` (full load: stops music `$19FE4`/`$19FBA`, reads level module at `$54E00` via `$921A`, `jsr $54E00`, runs, returns), `$917E` (reload when `$E04` != `$8F98`).

## 6. Level / tile / scroll / objects (M)
- Level module (`$54E00`..) supplies per-frame `level_frame` ($54E24: 42 insns, reads scroll position/timers, spawns objects through `$1008`-`$1010` free-list ops, `jmp (a2)` script stepping at $5594A/$55B9C), `level_init` ($54E0C: sets vars, big init chain up to $566A6), and map/tile/enemy-wave data tables referenced by header pointers. Per-level sizes 117-176 KB, code only ~3-5 KB of each.
- Scrolling is bitmap-blit based (no hardware scroll register use besides BPLxPT rewrite): vertical scroll implemented by updating plane pointers in the copper lists ($1014/$1038), with the tile/background blit routines in `$0E96`/`$1368`/`$1438` (M).
- Object system: 5 doubly linked lists (heads `$A88 $AEA $B4C $BAE $C10`), free list `$42A` (alloc/free at `$0FEE-$1012`), record layout `+0` active, `+2 handler ptr`, `+6/+A` gfx ptrs, `+$E/+$12` links, `+$44` id (H). `$35D4` runs `$3656` (call handler `jsr (a1)` at $3662) over each list then collision pass `$366A`. Enemy AI jump table at `$47D6` (19 handlers `$4894-$543A`).
- Input handling: IRQ3 reads JOY0DAT/fire each frame into `$A00/$A01`; keyboard via L2; menu loops use `$2026` wait + `$A00/$A01`.

## 8. Self-modifying / code-region writes
- Confirmed: only the crack stub's trainer patches (see memory-map.md): game `$5D84` (byte `$60`, `bhi`->`bra`), `$7B1C` (3 NOPs) and the start-level words `$7846`/`$784C` (no-op at default). **The recompiler should NOT bake these in** (unless a trainer build is desired).
- Level-module header words `$54E04` (written by `$90EC`, `$566CA`) are data in the header region (the first longs of the header execute as harmless `ori.b #n,d6` when entered via `jsr $54E00`, so `$54E04` content is **semantically code**: the recompiler must not translate those 12 bytes as anything but data; entry must be redirected to `$54E0C`).
- The anti-trace region `$7104-$763A` decrypts instructions at run time with a trace handler (not used on the live path, M).
- Remaining entries in `code_writes` of entrypoints.json are heuristic false positives (variables adjacent to decoded data), none confirmed.

## 9. What is incomplete / blocked
- No Ghidra/REA: no Java runtime; REA lacks an Amiga/68k loader. All analysis is capstone-based; names are heuristic. 
- Data-driven dispatch (object handlers `obj+2`, script streams, per-level `jmp (a2)`) cannot be fully resolved statically; discovered immediates + gap-sweep (95 low-confidence function starts) are included in the JSON with `confidence`. A dynamic trace (emulator running the game and recording executed PCs) is the right way to close this.
- Gap-swept entries (confidence `low`) may include data decoded as code; the recompiler should prefer traced PCs.
- Graphics ($1C400+), level maps, music module/sample data not parsed (belongs to asset lanes).
- Disc-1 `c/add21k` helper not analysed (irrelevant to the game).
